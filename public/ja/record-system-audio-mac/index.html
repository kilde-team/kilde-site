Mac が再生している音を録る

仮想オーディオドライバ不要のシステム音声収録

先に結論: 会議の相手の声・動画の音・アプリの音楽など「Mac から出ている音」を 録りたいなら、macOS 標準の画面収録は使えません — 録れるのはマイクだけだからです。 kilde なら、システム音声をネイティブに収録できます。画面といっしょでも、 音声だけでも、ワンコマンドで。仮想オーディオドライバ (Soundflower や BlackHole) の インストールも不要です。

なぜ標準の収録は無音になるのか

macOS の画面収録で選べる音声はマイクだけです。スピーカーから出ている音 — 通話の相手の声、再生中の動画の音 — は入力として現れず、ファイルに入りません。代わりに マイクで部屋の音を拾うと、エコーやキーボード音が混ざり、相手の声はくぐもります。

従来の回避策は Soundflower や BlackHole といった仮想オーディオドライバを挟んでシステム音を 入力に回すもので、確かに動きます。ただセットアップと経路の調整が必要で、macOS を更新する たびに「まだ動くか」の不安がつきまといます。

kilde でシステム音声を録る

  1. インストール。 メニューバーアプリは Mac App Store から。 CLI は Homebrew またはリリースバイナリ で入ります。
  2. 環境チェック。 kilde doctor が画面収録の権限などを確認し、 足りないものは案内してくれます。
  3. 収録。 kilde rec demo.mov で、画面と Mac が再生している音を 1 つのファイルに収録します。メニューバーアプリならディスプレイを選んで録画開始。
  4. 安全に停止。 Ctrl+C (やメニューバーの停止ボタン) でもファイルは必ず ファイナライズされます — 書きかけの録画が残ることはありません。

音だけを録る

あとで文字起こししたい会議の音声や講義・インタビューなど、映像が要らない場合は 音声のみの収録を:

kilde rec --no-video meeting.m4a

システム音声の M4A が得られます (マイクをミックスするのも、 --audio-tracks separate でトラックを分けるのも自由です)。

ドライバのインストールが要らない理由

kilde は ScreenCaptureKit — macOS が標準の画面収録に使うのと同じフレームワーク — の上に 作られています。Mac が再生している音をソースで拾うので、経路の設定もデバイスの作成もなく、 macOS を更新しても壊れる仕組みがありません。無料・オープンソース・MIT ライセンスです。
